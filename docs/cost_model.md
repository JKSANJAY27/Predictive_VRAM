# Module 6: Cost Model and Candidate Scoring

## 1. Architectural Role & Pipeline Overview

Module 6 translates candidate partition plans generated by Module 5 into transparent, normalized, multi-objective operational cost scores.

```
Telemetry -> RuntimeState -> StateBuffer -> Prediction -> Candidate Generation -> COST MODEL (Module 6) -> Controller (Module 7) -> Migration (Module 8)
```

### Critical Separation of Concerns
- **Module 6 computes cost and utility**: It evaluates $J(a)$, quantifies component trade-offs, normalizes scales, and preserves provenance.
- **Module 7 makes decisions**: Module 6 strictly does **NOT** implement `argmin`, keep/migrate selection, threshold $\theta$, cooldown, hysteresis, or runtime migration.

---

## 2. Objective Function Formulation

For any proposed candidate plan $a$, the composite cost $J(a)$ is defined as:

$$J(a) = \alpha \cdot \tilde{L}(a) + \beta \cdot \tilde{C}(a) + \gamma \cdot \tilde{M}(a) + \delta \cdot \tilde{E}(a) + \epsilon \cdot \tilde{P}_{\text{switch}}(a)$$

Where:
- $\tilde{L}(a)$: Normalized per-token inference latency
- $\tilde{C}(a)$: Normalized steady-state inter-tier communication volume
- $\tilde{M}(a)$: Normalized peak memory pressure across active execution tiers
- $\tilde{E}(a)$: Normalized energy proxy consumption
- $\tilde{P}_{\text{switch}}(a)$: Normalized one-time repartitioning and migration penalty
- $\alpha, \beta, \gamma, \delta, \epsilon \ge 0$: Configurable multi-objective weights

Lower composite score $J(a)$ indicates a more desirable configuration.

---

## 3. Cost Components & Exact Mathematical Models

### 3.1 Latency Model ($L(a)$)
Token execution latency is decomposed into three additive components:

$$L(a) = L_{\text{compute}}(a) + L_{\text{comm}}(a) + L_{\text{queue}}(a)$$

1. **Compute Latency ($L_{\text{compute}}$)**:
   $$L_{\text{compute}}(a) = \sum_{t \in \text{active}(a)} N_{\text{layers}}(a, t) \times r_{\text{compute}}(t)$$
   Where $r_{\text{compute}}(t)$ is the empirical compute rate per layer on tier $t$ (e.g., 8.0 ms/layer on User Device, 2.0 ms/layer on Edge A, 1.0 ms/layer on Edge B).

2. **Communication Latency ($L_{\text{comm}}$)**:
   $$L_{\text{comm}}(a) = \sum_{b \in \text{boundaries}(a)} \left( \frac{\text{ActivationBytes} \times 8}{B_{\text{effective}} \times 10^6} \times 1000 + \text{RTT} \right)$$
   Where $B_{\text{effective}}$ is the predicted or current bandwidth (Mbps), and $\text{RTT}$ is inter-tier round-trip latency. For monolithic execution ($\text{boundaries} = 0$), $L_{\text{comm}} = 0$.

3. **Queueing Latency ($L_{\text{queue}}$)**:
   Modeled proportionally to CPU/system load proxy when host utilization exceeds $50\%$.

---

### 3.2 Steady-State Communication Model ($C(a)$)
Estimates recurring per-token activation transmission volume:

$$C(a) = \text{boundaries}(a) \times \text{ActivationTensorSize}_{\text{MB}}$$

> [!IMPORTANT]
> **No Double Counting**: $C(a)$ strictly captures *steady-state recurring* activation flow during inference. One-time model weight or KV-cache migration traffic is modeled exclusively in $P_{\text{switch}}(a)$.

---

### 3.3 Memory Pressure Model ($M(a)$)
Evaluates headroom saturation across participating execution tiers:

$$M_{\text{pressure}}(a) = \max_{t \in \text{active}(a)} \left[ \frac{\text{RequiredMemory}(a, t)}{\text{UsableCapacity}(t)} \right]$$

- **Multi-Horizon Forecast Integration**: When a forecast trajectory exists, the model evaluates both current pressure and predicted peak pressure over the entire forecast horizon ($\max_{t, \tau} \text{Pressure}(t, \tau)$), guarding against near-future VRAM exhaustion.
- **Risk Escalation**: When memory pressure exceeds the configurable safety threshold ($\ge 0.85$), a non-linear penalty is applied:
  $$\text{Penalty} = \left( \frac{\text{Pressure} - 0.85}{1.0 - 0.85 + 0.01} \right)^2$$
- **UNKNOWN Preservation on CPU Host**: When physical VRAM telemetry is unavailable (`DataSource.UNAVAILABLE`), the status is preserved as `ScoreStatus.UNKNOWN`. Memory utilization is **never fabricated** as 0.0.

---

### 3.4 Energy Proxy Model ($E(a)$)
Estimates operational energy per inference step using empirical tier power proxies:

$$E(a) = \sum_{t \in \text{active}(a)} \left( \frac{L_{\text{compute}}(a, t)}{1000} \times P_{\text{tier}}(t) \right) \quad [\text{Joules}]$$

Where $P_{\text{tier}}(t)$ is the baseline power proxy (e.g., 5W for User Device, 45W for Edge A, 150W for Edge B). Tagged as `DataSource.ESTIMATED`.

---

### 3.5 Switching Cost Model ($P_{\text{switch}}(a)$)
Quantifies the transition and disruption penalty from the active plan $a_{\text{current}}$ to candidate $a$:

$$P_{\text{switch}}(a) = w_{\text{layer}} \cdot \Delta_{\text{layers}} + w_{\text{bound}} \cdot (\text{ShiftDist} + 0.5 \cdot \text{CutEdits}) + w_{\text{kv}} \cdot \text{KV}_{\text{MB}} + w_{\text{disrupt}} \cdot |\text{AffectedTiers}|$$

#### Core Invariants:
1. **Identical Plan Invariant**: If candidate $a$ is identical to $a_{\text{current}}$, $P_{\text{switch}}(a) = 0.0$.
2. **Transition Cost Invariant**: If candidate $a \ne a_{\text{current}}$, $P_{\text{switch}}(a) > 0.0$.
3. **KV-Cache Migration**: Estimates KV-cache transfer volume based on the fraction of model layers migrated:
   $$\text{KV}_{\text{migrated}} = \text{KV}_{\text{total}} \times \frac{\Delta_{\text{layers}}}{N_{\text{total\_layers}}}$$
4. **Structural Delta Reuse**: Reuses `compare_plans(current, candidate)` from Module 5 without duplicate logic.

---

## 4. Normalization Methodology

To prevent high-magnitude metrics (e.g. latency in ms) from dominating lower-magnitude metrics (e.g. memory ratios), all raw metrics are normalized using configured scale reference denominators:

$$\tilde{x} = \frac{x}{\text{Scale}_x}$$

| Metric | Raw Unit | Configured Scale | Normalized Value |
|---|---|---|---|
| Latency ($L$) | milliseconds | $100.0\text{ ms}$ | $\tilde{L} = L / 100.0$ |
| Communication ($C$) | megabytes | $10.0\text{ MB}$ | $\tilde{C} = C / 10.0$ |
| Memory Pressure ($M$) | ratio $[0, \infty)$ | $1.0$ | $\tilde{M} = M / 1.0$ |
| Energy ($E$) | Joules | $10.0\text{ J}$ | $\tilde{E} = E / 10.0$ |
| Switching ($P_{\text{switch}}$) | structural units | $1.0$ | $\tilde{P} = P / 1.0$ |

> [!IMPORTANT]
> **Fairness Constraint**: All candidates evaluated within a single optimization step share the exact same normalization scales. Per-candidate independent normalization is strictly prohibited.

## 5. Experimental Baselines & Ablation Support

The CostModel provides first-class support for isolating cost components:

```python
from src.cost import CostModel, CostWeights

# Baseline 1: Latency-Only Controller Input
cm_latency = CostModel(weights=CostWeights.latency_only())

# Baseline 2: Network-Aware (Latency + Comm)
cm_network = CostModel(weights=CostWeights.network_aware())

# Baseline 3: Memory-Aware (Latency + Memory Pressure)
cm_memory = CostModel(weights=CostWeights.memory_aware())

# Baseline 4: Switching Penalty Ablation (epsilon = 0.0)
cm_no_switch = CostModel(weights=CostWeights.no_switching())

# Baseline 5: Reactive Mode (forecast = None)
score_reactive = cm.score(candidate, state=current_state, forecast=None)
```
